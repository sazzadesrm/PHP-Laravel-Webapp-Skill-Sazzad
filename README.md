# webapp-php-laravel-sazzad

A Claude Code skill for rebuilding legacy PHP/SQL applications as fresh, secure, responsive Laravel SaaS applications.

The skill is tailored for **CMMS — Corporate Money Monitoring System**.

## Product architecture

- Laravel 13 / PHP 8.5 target, subject to hosting compatibility
- MySQL with InnoDB
- React 19 + TypeScript + Inertia 3
- Tailwind CSS 4 + shadcn/ui
- Vite-built assets
- Shared-hosting deployment package with a browser-based installer
- In-app preview and mandatory download for PDF, XLSX, CSV, PNG, and JPG/JPEG

## Install as a Claude Code skill

Copy `skills/webapp-php-laravel-sazzad/` into your project's `.claude/skills/` directory:

```text
your-project/
└── .claude/
    └── skills/
        └── webapp-php-laravel-sazzad/
            ├── SKILL.md
            └── references/
```

Alternatively, install user-wide under `~/.claude/skills/`.

Restart Claude Code or start a new session, then ask it to use `webapp-php-laravel-sazzad`.

## GitHub use

1. Create a GitHub repository.
2. Upload this repository's contents to the repository root, or push the extracted folder using your preferred Git client.
3. Keep the skill folder at `skills/webapp-php-laravel-sazzad/`.
4. In any application repository, copy that skill folder into `.claude/skills/`.

The included GitHub Actions workflow validates the skill package structure. It does not build or deploy the CMMS application.

## Beginner-friendly setup and database connection

The CMMS deployment specification requires a browser-based, plain-language setup wizard for shared hosting. Users enter database host/name/username/password, test the connection, and let the installer configure Laravel and run migrations when the host permits it. A protected settings page supports safe connection changes with validation-before-apply, rollback to the previous working connection, masked secrets, and clear troubleshooting. No terminal, manual SQL import, or manual `.env` editing should be required in the supported no-command deployment path.

## Authentication, profiles, and master data

The specification includes email/phone authentication, optional Google/GitHub/Facebook/Microsoft OAuth, secure remember-me sessions, password reset, TOTP 2FA, one-time backup codes, WebAuthn passkeys, account recovery, device/session management, premium desktop/mobile login screens, profile photo/settings, and permission-controlled master data. Select dropdowns support an explicit manual-entry/Other path where business rules permit it. Provider integrations require real credentials and end-to-end verification; no provider is represented as working before setup.
